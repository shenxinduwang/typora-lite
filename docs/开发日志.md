# 开发日志 · Typora-Lite

记录开发过程中真实踩到的坑与解法，供后续维护和同类项目参考。按主题归类，不严格按时间。

## 1. 工具链 / 环境

**症状**：`cargo build` 时 `rustc` 报 `link: extra operand ... Try 'link --help'`、`link.exe returned an unexpected error`，看起来像"装了却没链接器"。

**根因**：这是 **Git Bash 的 coreutils `link`（`/usr/bin/link`，用来建硬链接）抢占了 `link.exe` 这个名字**，而机器上根本没装 MSVC 的 `link.exe`。`which link` 指向 `/usr/bin/link` 即可确诊。rustc 的 msvc 目标必须用真正的 MSVC 链接器 + Windows SDK 导入库（`kernel32.lib` 等）。

**解法**：装 VS Build Tools 的 C++ 工作负载（含 MSVC + Windows SDK）：
```
winget install -e --id Microsoft.VisualStudio.2022.BuildTools \
  --override "--passive --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```
装完 `cargo` 仍不在 Git Bash 的默认 PATH，构建前 `export PATH="$USERPROFILE/.cargo/bin:$PATH"`。装好后 rustc 会通过 vswhere 自动定位 MSVC，无需手动配 PATH。

## 2. CodeMirror 6 语法节点 / 装饰

- **围栏代码块的节点名是 `FencedCode`，不是 `CodeBlock`**。按 `CodeBlock` 匹配会静默漏掉整块样式。用"临时把遍历到的节点名塞进 `window.__NODES__` 再 dump"的办法拿到了权威名单：`ATXHeading1..6 / Emphasis / StrongEmphasis / InlineCode / FencedCode(CodeMark/CodeInfo/CodeText) / Strikethrough(StrikethroughMark) / Task(TaskMarker) / Table / TableHeader / TableRow / TableCell / TableDelimiter / ListMark / Blockquote(QuoteMark) / HorizontalRule`。
- **GFM 启用**：`import { GFM } from "@lezer/markdown"` → `markdown({ extensions: GFM })`（任务列表扩展叫 `TaskList`，不是 `Task`）。不开 GFM 时表格/任务/删除线连语法节点都没有。
- **`WidgetType` 从 `@codemirror/view` 导出，不是 `@codemirror/state`**。导错包会让 `import` 抛 `does not provide an export named 'WidgetType'`，`EditorView` 构造期直接挂掉、页面白屏（且 `read_console_messages` 不一定显示 uncaught）。排查法：在页面里 `import('/src/main.js?cb='+Date.now()).catch(e=>window.__r=e.stack)` 抓真实栈。
- **同一行只能有一个 `Decoration.line`**。引用块里的标题 `> # x` 会让同一行同时命中"标题行样式"和"引用行样式"，若分别 push 会在 `RangeSet.of` 抛错白屏。解法：用 `Map<lineFrom, Set<class>>` 先按行聚合，最后每行只产出一个合并 class 的行装饰。
- **中文 IME**：`ViewPlugin.update` 里加 `if (u.view.composing) return;`，合成期不重建装饰，否则候选词被打断掉字。
- **可折叠标记（Typora 关键手感）**：用 `caretIn(父节点范围)` 判断光标是否在某段内——在内显示原始 `# ** ` >`，在外 `Decoration.replace({})` 隐藏。

## 3. 任务复选框点击定位

**症状**：把 `[ ]` 用 replace widget 渲染成复选框后，点击切不动 / 切错行。

**根因**：replace widget 没有文本宽度，`view.posAtCoords({x,y})` 按像素反查会**跨行错位**。

**解法**：从被点的 DOM 反查——`event.target.closest('.cm-taskbox')` 拿到元素，再 `view.posAtDOM(el, 0)` 得到精确文档位置（== `TaskMarker.from`），据此定位并 `dispatch` 改源码。

## 4. 文件打开 / 双击关联

- **App 不会自动接收命令行文件参数**：要在 Rust 里 `std::env::args()` 捕获路径，存进 managed state，用 `take_launch_file` 命令回传给前端载入；前端启动后取一次。
- **`setTitle` 没生效 / 标题不变**：Tauri v2 下 `getCurrentWindow().setTitle()` 需要 capability 授予 `core:window:allow-set-title`，否则调用被权限拒绝（这里被静默 catch 掉，表现为"标题一直停在默认"）。补进 `capabilities/default.json` 即可。
- **双击打开看到的却是"默认示例内容"**：本质是**多实例**——之前测试残留了一个显示示例的窗口还开着，双击又起了新窗口叠在后面，看到的是旧窗口。解法：上 `tauri-plugin-single-instance`，二次启动时不再开新窗口，而是 `app.emit("open-file", path)` 把路径转发给已存在窗口 + `set_focus()`；前端 `listen("open-file", e => loadFile(e.payload))` 在当前窗口里换文档。
- **用户级关联免管理员**：`.md` 当前没有 UserChoice 覆盖时，写 `HKCU\Software\Classes\.md` 默认值=自定义 ProgId，再给 ProgId 配 `shell\open\command` = `"...\typora-lite.exe" "%1"` 即可直接生效（`HKCU\Software\Classes` 会并入并对本用户优先于 HKLM）。`%1` 外层要带引号以兼容含空格路径。
- **右键"新建 → Markdown Document"**：给 ProgId / 扩展名加 `ShellNew` 且 `NullFile=""`（新建空文件），`IconPath` 指到 exe 取图标。
- **验证双击**：`Invoke-Item '某.md'` 或 `Start-Process exe -ArgumentList '某.md'` 都走 Shell 关联，等价于双击；再用 `Get-Process typora-lite | % MainWindowTitle` 读原生标题确认加载的是所选文件而非示例——这是没有截图权限时最可靠的"内容已载入"证据。

## 7. 关联做进安装包 & CRLF 行尾坑

- **baked 关联**：`tauri.conf.json` → `bundle.fileAssociations`。字段仅 `ext`+`description` 被接受，写 `mime` 会报 schema `Additional properties are not allowed ('mime' was unexpected)` 并中止构建。装完后安装器自动建 ProgId（**用首个扩展名命名，如 `md`**）、`.md` 默认值指向它、`shell\open\command = "<exe>" "%1"`，双击即生效，无需再手动导 reg（实测：删净手动键→重装→`.md default=md`、双击标题正确）。安装器**不加**右键"新建"，那仍需 `.reg` 里的 `ShellNew`。
- **CRLF 导致"一打开就是脏"**：CM6 文档模型把行尾归一成 `\n`，而 `read_text_file` 进来的 Windows 文本是 `\r\n` → `docText()`(LF) 恒 ≠ `lastSaved`(CRLF) → 打开即显示未保存圆点，保存还会悄悄把文件变 LF。修法：脏判定用 `normEol()`（`/\r\n?/g→\n`）两边归一比较；载入时记 `originalEolCRLF = text.includes("\r\n")`，保存时若原为 CRLF 再 `\n→\r\n` 还原，保持原文件行尾不变。
- **右键"新建"做进产品（免导 reg）**：安装器的 `fileAssociations` 不带 `ShellNew`，所以右键新建得自己补。方案：App `setup()` 里用 `winreg` 写 `HKCU\Software\Classes\<ext>\ShellNew`(NullFile+IconPath) 和自建 ProgId（含 `shell\open\command`），**只加 ShellNew/OpenWith、不覆盖 `.md` 默认值**（否则每次启动会把用户改过的默认编辑器抢回来）。装完首启即自注册。坑：写完资源管理器仍缓存"新建"子菜单，要 `ie4uinit.exe -show` 或重启 explorer 才刷新出来——验证时别误判成没生效，直接回读 `HKCU\...\Classes\.md\ShellNew` 是否存在最可靠。
- ~~**待做：卸载清理自注册键**~~ → **已做**，见第 10 节（`installer-hooks.nsh` 的 `NSIS_HOOK_POSTUNINSTALL`，实测卸载后自注册键全部清干净、其他应用的登记值完好保留）。

## 8. 数据安全 / 编码 / 性能（代码审查修复轮）

- **Ctrl+Z 会"撤销回上一个文件"**：载入新文件若用 `dispatch` 整文替换，这次替换会进 `history()` 撤销栈——打开 A → 打开 B → Ctrl+Z，窗口里出现 A 的内容而 `currentPath` 还是 B。解法：载入/新建统一走 `view.setState(EditorState.create({doc, extensions}))` 整体重建，撤销历史随之清空；扩展数组提成公共 `baseExtensions` 共用（setState 会重置光标/滚动，对文件切换可接受）。
- **关窗拦截的两半不对称（坑王）**：`onCloseRequested` 里"取消关闭"的 `event.preventDefault()` 是本地标志位，**不需要权限**；而"确认后放行"由 JS 侧调 `destroy()` 完成，`core:default` **不含** `core:window:allow-destroy`。症状极迷惑：文件已保存、标题脏点已消失，窗口却关不掉、进程不退（destroy 被权限拒绝且无提示）。只有真机点一遍"保存并退出"才能暴露，capabilities 里补 `core:window:allow-destroy` 即愈。
- **GBK/ANSI 文件"双击没反应"**：`fs::read_to_string` 只认 UTF-8，中文 Windows 常见的 GBK .md 直接读取失败，叠加"错误只进 console"就完全静默。解法：Rust 端 `fs::read` 拿 bytes → 按 BOM 识别 UTF-8 BOM / UTF-16LE/BE → 严格 UTF-8 失败回退 `encoding_rs::GBK`；命令返回 `{text, encoding}`，**保存时按原编码写回**（utf16/bom 的补回 BOM）。浏览器兜底用 `TextDecoder('utf-8',{fatal:true})` 失败转 `TextDecoder('gbk')`（Chromium 只能解不能编，浏览器保存统一 UTF-8）。验证法：`iconv -f UTF-8 -t GBK > 造文件`，保存后 `iconv -f GBK -t UTF-8` 回读 + `file` 确认仍是单字节编码。
- **保存非原子**：`fs::write` 直接覆盖，写一半崩溃/断电文件即截断损坏。解法：同目录写 `xxx.md.~tmp` 再 `fs::rename`——Windows 上 rename 等价 `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`，可覆盖已存在目标且同盘原子；失败删临时文件。
- **单实例转发竞态**：前端 `listen("open-file")` 注册晚于两个 `await import/invoke`，首实例启动窗口期内二次双击的 `emit` 会丢。解法：listen 提到最前 + Rust 端转发路径同时 push 进 `PendingOpen(Mutex<Vec<String>>)` 队列，前端订阅完成后 `take_pending_files` 补捞一遍。
- **vite dev server 被 cargo 搞崩**：vite 默认监听项目根，cargo 编译时锁 `src-tauri/target` 下的 dll，Windows 上 chokidar 对被锁文件 `watch` 抛 `EBUSY` 直接把 dev server 打挂（本次实测踩到：cargo check 与 vite dev 并行，vite 退出码 1）。解法：`vite.config.js` 加 `server.watch.ignored: ["**/src-tauri/target/**"]`。
- **每键一次 setTitle IPC + O(n)×2 脏比较**：原 `updateListener(docChanged)` 里每键 `docText()` 物化全文、`normEol` 正则跑两份字符串、并无条件 IPC 改窗口标题，大文档打字会卡。解法：CM 文档恒为 LF，把"上次保存内容"归一成 LF 缓存为 `lastSavedNorm`，脏判定退化为一次字符串比较；标题字符串没变不碰 DOM/IPC；UI 刷新合帧到 rAF。
- **选区颜色写 `::selection` 是死样式**：`drawSelection()` 用自绘 `.cm-selectionBackground` 渲染选区并把原生 `::selection` 置透明。且聚焦态 CM 内建选择器是 `.cm-focused > .cm-scroller > .cm-selectionLayer .cm-selectionBackground`，特异性更高，普通选择器会被压成默认紫灰 `#d7d4f0`——必须用 `&.cm-focused > .cm-scroller > ...` 全路径同特异性覆盖（后挂载者胜）。排查法：遍历 `document.styleSheets` 找 `selectionBackground` 的全部规则对比特异性。
- **工具栏按钮抢焦点**：点完 新建/打开/保存 焦点停在按钮上，继续打字"没反应"。各 handler 末尾 `view.focus()` 一行修复。
- **分割线只是"带下划线的 `---`"**：`HorizontalRule` 节点没有可隐藏的子标记，光标不在该行时用 replace widget 渲染成真横线（`role="separator"`），光标进入显示原文；行装饰只留 margin。
- **测试基建备忘**：自动化造编码文件用 `iconv`（GBK）/`printf '\xef\xbb\xbf'`（BOM）；原生窗口内容验证用 `get_app_state` 的窗口级截图（全屏截图会被别的应用遮挡）；浏览器端 `locator.press("x")` 在 IAB 后端不产生文本输入，要用 `locator.type("x")`，但 `press("Control+z")` 等组合键正常。

## 9. 功能开发：查找替换 / 代码高亮 / 列表手感 / 拖放 / 大纲

### 查找/替换

- **接入零坑**：`@codemirror/search` → `search({ top: true })` + `highlightSelectionMatches()`，`searchKeymap` 插在 `defaultKeymap` 之前即可（Mod-f / F3 / Mod-g / Mod-d 全选同词 / Esc 关闭都自带）。
- **自动化测试的坑**：CM 搜索框提交查询绑定的是 **`onkeyup` / `onchange`，不是 `input` 事件**（读 `node_modules/@codemirror/search` 源码确认）。真实用户敲键盘没任何问题，但合成输入（`fill`/`type`/手动派发 `input` 事件）不产生 keyup → 高亮永远不出现、Enter 也不跳转，极易误判成"搜索坏了"。验证法：`el.dispatchEvent(new KeyboardEvent("keyup", {bubbles:true}))`。

### 列表续写 / 缩进

- **白干了一件事，但值得**：按方案自研了 `continueList`（回车续写/有序递增/任务重置/空项退出），真机测试发现**行为全对但代码从未执行**——`@codemirror/lang-markdown` 自带 `markdownKeymap`，且用 **`Prec.high`** 注册了 `Enter → insertNewlineContinueMarkup`（源码 `support.push(Prec.high(keymap.of(markdownKeymap)))`），优先级压过任何普通 `keymap.of`。续写、`2. → 3.` 递增、`[x] → [ ]` 重置、空项删标记退出、引用前缀延续，内建全都有。解法：删掉自研 Enter 命令，只补内建没有的 **Tab/Shift+Tab 列表缩进**（前缀内加/删 2 空格，支持多行选区，代码块内不接管）。
- **教训**：接入现成扩展前先 `grep node_modules/<pkg>/dist/index.js` 看它注册了哪些 keymap/优先级，别凭文档假设"没有"。合成 keydown（`new KeyboardEvent("keydown", {cancelable:true})`）能触发 CM keymap 命令，但合成输入的插入行为（beforeinput 路径）在 IAB 下会双发，测试要在全新标签页做并逐步断言文档行。
- 验证基线：`- a` + Enter → `- `；`1. one` + Enter → `2. `；`- [x] t` + Enter → `- [ ] `；空项 Enter → 删标记退出；Tab → `  - b`；Shift+Tab → `- b`。

### 大纲侧栏

- **数据源零成本**：装饰系统已经在遍历语法树，大纲只是同一棵树再 iterate 一遍 `ATX|SetextHeading[1-6]`。关键点：大纲要**全文档**标题，用 `ensureSyntaxTree(state, state.doc.length)` 强制解析到文末（`syntaxTree` 只返回已解析部分，长文档打开瞬间会缺尾部标题）。
- **性能**：docChanged 防抖 300ms 后重建（全文解析不卡每键）；selectionSet 只更新 active class（不重建 DOM）。点击跳转 = `view.dispatch({selection, effects: EditorView.scrollIntoView(pos, {y:"start"})})`。
- **布局**：原来 body 是 `toolbar + #editor` 两行 flex，加侧栏改成 `toolbar + #main(#outline + #editor)`；`#editor` 要补 `min-width: 0`，否则 flex 子项内容宽会撑破容器。
- IAB 偶发 locator click 不可行性误报（元素明明可见），用 `evaluate(() => el.click())` 直驱即可。

### 拖放打开

- **Tauri 的 drag-drop 与 HTML5 事件互斥**：窗口配置 `dragDropEnabled: true`（默认即 true）时 WebView2 会吞掉页面内的 HTML5 `drop` 事件，必须用 `getCurrentWebview().onDragDropEvent()` 监听原生事件（payload 分 enter/over/drop/leave，drop 带 `paths`）；浏览器兜底走 HTML5 `dragover/drop` + `dataTransfer.files`。两路共用脏确认（`confirmDiscard`）与解码（`decodeBrowserBytes`，从 pickBrowserFile 重构出的公共函数）。
- **测试基建**：合成拖放用 `new File([...]) + DataTransfer.items.add(file) + new DragEvent("drop", {dataTransfer: dt})` 派发到 document 即可全链路验证（文件名采用、编码解码、渲染）。IAB 的 `tab.reload()` 可能命中 bfcache 导致**页面跑旧 JS**（新功能"没生效"的假象），用全新标签页验证最可靠。

## 10. 跨机部署事故：.reg 路径污染 & 卸载清理闭环

- **事故**：`md-association.reg` 在另一台电脑（用户名不同）导入后双击 .md 打不开——reg 里硬编码了 `C:\Users\<用户名>\AppData\Local\...` 绝对路径，且 **.reg 导入不展开环境变量**，换机即指向不存在的程序。而它提供的功能（默认关联/右键新建/打开方式登记）安装器 `fileAssociations`（按实际安装路径写）和 App 首启 `ensure_shell_new()`（按 `current_exe()` 写、每次启动自愈）本来就已全覆盖。**解法：文件直接删除**；手动改关联的正确姿势是"右键 → 打开方式 → 始终使用此应用"。教训：任何"便携配置文件里写死本机路径"的兜底方案都是跨机定时炸弹，全项目 `grep -rn "C:\\\\Users"` 扫一遍确认无残留。
- **卸载钩子实现**（原第 7 节待做项）：`src-tauri/installer-hooks.nsh` + `tauri.conf.json → bundle.windows.nsis.installerHooks`，`NSIS_HOOK_POSTUNINSTALL` 里清理 App 运行时自注册的键。两个关键细节：
  1. **只删自己的**：`OpenWithProgids` 下实测还登记着其他应用的 ProgId（形如 `xxxMD.*`），只能 `DeleteRegValue` 删 `Typora-Lite.md` 这一个值，键用 `/ifempty` 收尾；
  2. **悬挂默认值**：Tauri 卸载器删 ProgId（`md`/`markdown`）但**不删** `.md`/`.markdown` 的默认值，留下指向已删 ProgId 的悬挂关联——钩子里 `ReadRegStr` + `StrCmp` 仅当默认值仍等于自家 ProgId 名时才 `DeleteRegValue`，用户改过的默认绝不碰。
- **验证闭环（本机实测）**：基线记录 → 静默卸载（`uninstall.exe /S`）→ `Typora-Lite.md` ProgId、`.md`/`.markdown` ShellNew、OpenWithProgids 自家值、悬挂默认值全部清零且第三方应用登记的 ProgId 完好 → 重装后 `.md default=md`、启动正常、首启自注册恢复。装/卸真正闭环。
- 遗留说明：`UserChoice`（`FileExts\.md\UserChoice`）是 Windows 托管项且带哈希校验，卸载器一律不动它，属正常行为。

## 14. v0.2.2 二次评审修复轮（code-reviewer 子代理复审收口）

- **失败图片反复重试 IPC（真问题，上轮漏修）**：失败路径缓存的是 `null`（假值），`if (cached)` 真值判断导致每次装饰重建都重发注定失败的 `read_asset_base64`——注释写"失败不再重试"但逻辑没做到。修法：`imageSrcCache.has(key)` 判存三分支（命中真值→设 src；命中 null→直接标 broken；未命中→loading+解析）。远程 http(s) 图在离线设计下本就不显示，此修让它稳定停在 broken 态、不再骚扰。
- **启动竞态真正修掉（上轮只记录未修）**：崩溃恢复确认框等 await 期间事件循环照常处理，此时收到 open-file → `loadFile` 先执行完 → 恢复分支 `applyLoadedText(draft)` 把它静默覆盖。修法：`startupPending` 缓冲 + `startupDone` 标志，启动流程结束后与 Rust `take_pending_files` 队列一起统一 `loadFile`（串行化后脏确认逐个弹、不会叠加）。

- **图片 title 解析错误 → 永久 broken**：`parseImageNode` 旧正则 `[^)]*` 把 `![alt](src "title")` 的 `src "title"` 整段当 src，解析必失败且被永久缓存。修法：`([^)\s]+)(?:\s+"[^"]*")?`——src 取第一个空白前 token、可选双引号 title 剥离。`![a]()`/裸空格路径等非法形式退化为显示原文（与 CommonMark 一致）。
- **拖放图片缺 2MB 守卫**：粘贴路径有 data URL 2MB 上限，浏览器拖放路径却手拼 data URL 无检查，大图直接写爆 localStorage 草稿。修法：拖放复用 `insertImageBytes`（同路守卫 + alt 文件名派生），错误处理无双弹窗。
- **loadFile 串行化（子代理复审 I-1）**：启动竞态修复把原"启动期覆盖"压缩到"drain 期窄窗口"——drain 的 `await loadFile` 期间新事件 fire-and-forget 并发，最坏双确认框叠加+后者被覆盖。修法：`loadFile` 包一层 promise 链排队（`doLoadFile` 保持原逻辑），连开请求逐个执行、末者不再任意覆盖先者。

## 17. v0.3.0 表格真渲染轮（方案 A：block widget + 点击进格）

「待扩展」头条落地。参考对象 Tydora（zuorn）的架构是 **TipTap 3.x（ProseMirror 文档模型）做 WYSIWYG + CM6 只做源码模式**，表格靠 `@tiptap/extension-table` 渲染成真表格节点——它能"点击单元格原地编辑"是因为文档模型本身就是富节点。本项目是**单一 CM6 文本模型 + 装饰**（打字即渲染是唯一卖点），照搬双编辑器架构 = 推翻定位。定案**方案 A**：光标不在表内时整表 `Table` 节点 block widget 渲染真 `<table>`，点击单元格 `posAtDOM` 反查源码位置、光标进表显示源码编辑——与全项目 `caretIn`「焦点即编辑」心智一致，零依赖。

### CM6 深水区五坑（本轮核心成本，全部有据可查）

1. **`EditorView.atomicRanges` 是 facet 不是函数**：`EditorView.atomicRanges(fn)` 直接抛 "is not a function"，必须 `EditorView.atomicRanges.of(fn)`——且 facet 输入值类型是 `(view) => RangeSet`。
2. **block 装饰禁止经 ViewPlugin 下发**：`Decoration.replace({block:true})` 放进 ViewPlugin 的 decorations 会在渲染期抛 "Block decorations may not be specified via plugins"（源码依据：`@codemirror/view` dist 的 `TileUpdate.emit` 里 `disallowBlockEffectsFor[index]` 按**装饰来源**判定——facet 输入是函数（插件路径）即禁止，StateField `provide: f => EditorView.decorations.from(f)` 的静态值放行）。解法：整表 block replace 独立成 `tableDecoField` StateField。
3. **facet 只接受纯值**：最初把字段值做成 `{decorations, atomic}` 包装对象经 `from(f, get)` 下发，`HeapCursor.from` 报 `undefined.isEmpty`——状态字段值必须就是 DecorationSet（或给 getter 且确认该版本语义），最终拆成 **两个纯值 StateField**（decorations / atomic 各一）最稳。
4. **atomicRanges 值必须是 RangeSet**：给普通 `{from,to}` 数组会在光标移动时炸 `set.between is not a function`（消费端调 `set.between`）。用 `Decoration.mark({}).range(from,to)` 承载后 `RangeSet.of` 之。
5. **flex 布局下宽表撑宽整个编辑器**：`.cm-scroller` 是 flex，`.cm-content` 作为 flex 项 `min-width:auto` 会被表格 max-content（1056px）撑开 → 整个编辑器横向滚动。解法三件套：`.cm-table { width:100%; overflow-x:auto; contain:inline-size }`——`contain:inline-size` 让固有宽度不外泄；同时 **td 必须重置从 `.cm-content` 继承的 `white-space/word-break/overflow-wrap`**（否则长 URL 在格内被断行，永远触发不了横向滚动）。实测 wrap 756 / scrollWidth 1056 / content 820，滚动收敛到表格内部。

### 实现

- `parseTable(state, tableNode)`：遍历 `Table` 子树（lezer-markdown 结构 `Table{TableHeader{TableCell...}, TableDelimiter(整行分隔), TableRow{TableCell...}}`；表头/数据行里的单个 `|` 也是 TableDelimiter 节点，用"含 `-`/`:` 之外字符"排除），提取单元格文本、**源码 range**、对齐（`:---:`/`:---`/`---:` → center/left/right）。
- `TableWidget`：真 `<table>` DOM（thead/tbody、斑马纹、hover），td 携带 `dataset.row/col`；**`eq` 只比文本与对齐**——cell 的绝对 range 会随前文编辑平移，不参与比较；点击时 `posAtDOM(wrap,0)` 反查 → `syntaxTree` 现场重解析找 Table → 按 (row,col) 取该单元格**当前** range → `dispatch({selection:{anchor}})`（杜绝旧闭包定位漂移）；越界回落 `line[col] || 末单元格`。
- 装饰镜像守卫：ViewPlugin 的 `case "Table"` 不再下发装饰，只登记 `widgetTables`（与 StateField 同规则：`!caretIn && parseTable` 成功），供同插件内所有会推 replace/line 的子 case 避让（LinkMark/URL、Image、TableDelimiter、TableHeader、TaskMarker、HIDE_MARKS 共 6 处）——漏一处就与整表 block replace 重叠 → CM 抛异常白屏。ListMark/CodeInfo/FencedCode/HR 几何上不可能落在单元格内（GFM cell 是 inline 内容），无需守卫。
- `atomicRanges` 原子化：方向键/点击坐标映射跳过被替换区，光标只能落在表格前后；进入靠点击单元格显式 dispatch。
- CSS：明暗两套 `--md-table-*` 变量；`width:100% + overflow-x:auto + contain:inline-size`。

### 追加修复：单元格行内渲染 + 「载入即渲染」（用户实测反馈）

用户真机对比 ima 发现：表格里 `` `package.json` `` 的反引号原样显示。两个根因，两个修复：

**坑 6（第 6 坑）：lezer-markdown 内联树里纯文本不是子节点，是子节点之间的间隙。** `InlineCode` 的子节点只有两个 `CodeMark`（内容是间隙，源码 L1421-1424）；`Emphasis/StrongEmphasis` 同理——`L1743-1751` 只把 Element 塞进 content，文本留在 mark 之间。直接遍历子节点会丢正文、且回退切片把闭合反引号带进 `<code>`（实测 `codeText = "package.json\`"`、`<strong>****</strong>` 无正文）。解法：`inlineSegments` 做**间隙填充**——遍历子节点时把 `[prevEnd, next.from]` 的间隙 emit 成 text 段；`InlineCode` 内容取两个 CodeMark 之间的间隙。现在单元格支持行内 code/em/strong/del 语义渲染（图片暂跳过），td 不再泄漏任何原始标记。

**坑 7（第 7 坑）：StateField 不追语法树 → 「载入即渲染」失效。** 真机诊断：restore 的 46KB 文档滚完全程 `tableSeen: 0`——新载入文档的语法树由 ParseWorker **后台渐进解析**，其 dispatch 不带 `docChanged/selection`，字段只认这两个标志就永远停在空树时算出的空装饰（症状：刚打开的文档表格不渲染，编辑一下才出现）。浏览器测试全程打字注入（有 docChanged）所以没抓到。解法：StateField 与插件镜像都追踪**语法树对象身份**（`syntaxTree(tr.state) !== cached` 即重算，O(1) 判等）；顺带把装饰/原子两个字段合并回单一 StateField（字段值就是 block replace 集合，直接复用为 atomicRanges，无重复计算）。
